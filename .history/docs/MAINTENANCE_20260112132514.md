# Maintenance Mode Documentation

## Overview

The maintenance mode feature allows administrators to temporarily restrict access to the admin dashboard for specific user roles while displaying a customizable maintenance message. This is useful during system updates, maintenance windows, or when troubleshooting issues that affect specific user groups.

## Features

-   **Role-Based Restriction**: Selectively restrict access by user role
-   **Admin Bypass**: Administrators always have access regardless of maintenance mode
-   **Custom Messages**: Display personalized maintenance messages in Arabic
-   **Public Form Access**: Public application forms remain accessible during maintenance
-   **Logout Option**: Restricted users can logout from the maintenance page

## Configuration

### Enabling Maintenance Mode

1. Navigate to **Settings → Training Settings** (`/Home/manage-training-settings`)
2. Scroll to the **"وضع الصيانة"** (Maintenance Mode) section
3. Toggle **"تفعيل وضع الصيانة"** (Enable Maintenance Mode) to ON
4. Enter a custom maintenance message in Arabic (e.g., "النظام تحت الصيانة. سنعود قريباً")
5. Select at least one user role to restrict:
    - **مشرف كلية** (College Supervisor)
    - **وزارة الصحة** (Ministry of Health)
    - **مدير التدريب العام** (General Training Manager)
6. Click **Save** to apply changes

### Settings Reference

| Setting               | Type       | Description                                    |
| --------------------- | ---------- | ---------------------------------------------- |
| `is_maintenance_mode` | Boolean    | Enables/disables maintenance mode              |
| `maintenance_message` | String     | Custom message displayed to restricted users   |
| `maintenance_roles`   | Array<int> | User role IDs that are affected by maintenance |

## Technical Architecture

### Components

#### 1. Middleware: `CheckMaintenanceMode`

**Location**: `app/Http/Middleware/CheckMaintenanceMode.php`

**Purpose**: Intercepts all web requests and enforces maintenance mode restrictions.

**Logic Flow**:

```
Request → Check if maintenance enabled → No → Allow
                                       → Yes → Check user role
                                               → Admin → Allow
                                               → Restricted role → Redirect to maintenance page
                                               → Other role → Allow
```

**Exclusions**:

-   Maintenance page itself (`/Home/maintenance`)
-   Logout routes
-   Livewire update requests
-   Filament asset requests
-   Public application forms (`/WelcomeForm*`)

#### 2. Settings Class: `TrainingSettings`

**Location**: `app/Settings/TrainingSettings.php`

**Purpose**: Stores maintenance configuration using Spatie Laravel Settings.

**Properties**:

-   `is_maintenance_mode`: Enable/disable flag
-   `maintenance_message`: Custom message text
-   `maintenance_roles`: Array of restricted role IDs

#### 3. Maintenance Page: `Maintenance`

**Location**: `app/Filament/Pages/Maintenance.php`

**Purpose**: Displays maintenance message and logout button to restricted users.

**Route**: `/Home/maintenance`

**Features**:

-   Full-screen blocking layout
-   Custom message display
-   Functional logout button
-   Hidden from navigation

#### 4. Constants Class: `MaintenanceConstants`

**Location**: `app/Constants/MaintenanceConstants.php`

**Purpose**: Centralizes all maintenance-related constants.

**Constants**:

-   Route patterns for exclusions
-   Default maintenance message
-   Path patterns

### User Roles

| Role ID | Constant       | Label (Arabic)     | Can Be Restricted |
| ------- | -------------- | ------------------ | ----------------- |
| 1       | `ROLE_ADMIN`   | مدير النظام        | ❌ Never          |
| 4       | `ROLE_MOH`     | وزارة الصحة        | ✅ Yes            |
| 5       | `ROLE_COLLEGE` | مشرف كلية          | ✅ Yes            |
| 8       | `ROLE_GTM`     | مدير التدريب العام | ✅ Yes            |

**Note**: Administrators (`ROLE_ADMIN`) are always exempt from maintenance mode restrictions.

## Usage Examples

### Example 1: Maintenance for College Supervisors Only

```php
// In settings:
is_maintenance_mode = true
maintenance_message = "النظام تحت الصيانة للمشرفين. سنعود قريباً"
maintenance_roles = [5] // ROLE_COLLEGE
```

**Result**: Only college supervisors see the maintenance page. All other users access the system normally.

### Example 2: Maintenance for Multiple Roles

```php
// In settings:
is_maintenance_mode = true
maintenance_message = "النظام تحت الصيانة. سنعود خلال ساعة"
maintenance_roles = [4, 5, 8] // MOH, College, GTM
```

**Result**: MOH users, college supervisors, and general training managers see the maintenance page.

### Example 3: Disable Maintenance

```php
// In settings:
is_maintenance_mode = false
maintenance_message = "" // Not required when disabled
maintenance_roles = [] // Not required when disabled
```

**Result**: All users access the system normally.

## Troubleshooting

### Issue: Infinite Redirect Loop

**Symptom**: Page keeps refreshing when accessing the maintenance page.

**Cause**: Middleware is also checking the maintenance page itself.

**Solution**: This is already handled by excluding the maintenance page path in the middleware. If this occurs:

1. Clear route cache: `php artisan route:clear`
2. Clear application cache: `php artisan optimize:clear`
3. Verify the middleware excludes `/Home/maintenance` in the `isExcludedRequest()` method

### Issue: Can't Logout from Maintenance Page

**Symptom**: Clicking logout doesn't work or redirects back to maintenance.

**Cause**: Logout route is being caught by the middleware.

**Solution**: Already handled by excluding logout routes. Verify:

-   `Home/logout` is excluded in middleware
-   `filament.*.auth.logout` route pattern is excluded

### Issue: Public Form Not Accessible During Maintenance

**Symptom**: Public application form shows maintenance page.

**Cause**: Middleware is not excluding the public form path.

**Solution**: Verify `WelcomeForm*` pattern is in the exclusions.

### Issue: Admin Seeing Maintenance Page

**Symptom**: Administrator users are blocked by maintenance mode.

**Cause**: Admin check is not working correctly.

**Solution**:

1. Verify the user has `role = 1` (ROLE_ADMIN)
2. Check the `isAdmin()` method in the User model
3. Ensure `isAdminUser()` method in middleware is called before role checks

## Best Practices

### 1. Message Guidelines

-   Keep messages concise and clear
-   Use Arabic for consistency with the application
-   Include expected duration if known
-   Provide contact information for urgent issues

**Good Example**:

```
النظام تحت الصيانة المجدولة حتى الساعة 2:00 مساءً.
للطوارئ، يرجى الاتصال على: 123-4567
```

### 2. Role Selection

-   Only restrict roles that are affected by the maintenance
-   Test with each role before enabling in production
-   Never restrict admins (they're automatically exempt anyway)

### 3. Testing Checklist

Before enabling maintenance mode in production:

-   [ ] Test with each restricted role
-   [ ] Verify admins can still access
-   [ ] Test public form accessibility
-   [ ] Verify logout button works
-   [ ] Check for redirect loops
-   [ ] Test browser console for errors

### 4. Communication

-   Notify affected users before enabling maintenance mode
-   Provide estimated downtime
-   Send notification when maintenance is complete

## Code Reference

### Checking Maintenance Status Programmatically

```php
use App\Settings\TrainingSettings;

$settings = app(TrainingSettings::class);

if ($settings->is_maintenance_mode) {
    // Maintenance is enabled
    $message = $settings->maintenance_message;
    $restrictedRoles = $settings->maintenance_roles;
}
```

### Checking if User is Restricted

```php
use App\Settings\TrainingSettings;

$settings = app(TrainingSettings::class);
$user = auth()->user();

if ($settings->is_maintenance_mode &&
    in_array($user->role, $settings->maintenance_roles) &&
    !$user->isAdmin()) {
    // User is affected by maintenance mode
}
```
